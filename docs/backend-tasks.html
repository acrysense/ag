Задачи для бэкенда — myag (единый список)

Только то, что делает бэк. Фронт по всем пунктам готов и в сборке. Порядок — по важности. Детали и обоснования — в docs/audit-myag-2026-09-01, контракт AG-1 — в docs/ag-1-options-endpoint.

1. AG-1 · Эндпоинт-справочник + убрать инлайн-списки — Critical

Причина: ERP-страницы генерируются на сервере 6–14 c (личный кабинет для сравнения — 0.12 c), HTML ~1 МБ. Виноваты вшитые в разметку ~2280 опций сотрудников + ~1161 опция фильтров, каждый заход из БД, без кеша.

  • Поднять GET /ajax/options.php по контракту (docs/ag-1-options-endpoint): параметры type/q/page/size/manager,

ответ {items:[{value,label}], total, hasMore}, скоуп по роли на сервере, только подготовленные выражения, кеш.

  • Перестать вшивать <option>/<label> в HTML и убрать window.AG_VISIT_EMPLOYEES_BY_MANAGER.
  • Повесить data-options-src на поля (образцы разметки — в ТЗ). Фронт-часть уже реализована и протестирована.
  • Цель: время сервера < 1 c, вес визитов < 200 КБ.

2. AG-2 · HTTP-заголовки безопасности — High

Сейчас нет ни одного: Content-Security-Policy, X-Frame-Options, Strict-Transport-Security, X-Content-Type-Options, Referrer-Policy. X-Powered-By: PHP/8.3.32 и Server: nginx/1.26.3 светят версии.

  • Добавить X-Frame-Options: SAMEORIGIN (или CSP frame-ancestors 'self'), HSTS,

X-Content-Type-Options: nosniff, Referrer-Policy.

  • server_tokens off, скрыть X-Powered-By.

3. AG-3 · Скоуп по роли + ПДн в HTML — High

Активная проверка показала: на руководительской роли серверный скоуп РАБОТАЕТ (список не расширить параметрами showAll/limit/all/manager/user_id; IDOR по визитам/сотрудникам закрыт; SQLi не найдено).

  • Подтвердить то же для роли РЯДОВОГО менеджера.
  • Убрать из HTML телефоны сотрудников (375…) и прочие ПДн, не нужные для отрисовки — уходит вместе с AG-1.

4. AG-13 · CSRF-токен на изменяющих + валидация загрузки — Medium

Фронт шлёт создание/изменение/удаление визита POST'ом с JSON-телом БЕЗ токена — бэк принимает действие по одной cookie-сессии (сигнатура CSRF).

  • Проверять Bitrix sessid на изменяющих эндпоинтах (visits-handler.php, подтверждение задач),

либо принимать только application/json и валидировать Origin/Referer.

  • Валидация загрузки аватара: тип и размер файла, неисполняемый каталог.
  • (Проверить эксплуатируемость можно curl'ом «Copy as cURL» из DevTools — но фикс нужен в любом случае.)

5. AG-7 · Поле «Период» в фильтре визитов — Medium

Сейчас поля нет → фильтрация по датам не работает. Вывести поле в группе data-page-fields="visits" (разметка есть в сборке), метод страницы должен читать DateStart/DateEnd.

6. AG-4 · Дубли <head>/скриптов + двойная Метрика — Medium

ShowHead() выводится дважды: битриксовые <link>, bx-core, meta — по 2 раза; скрипты визитов (calendar-cta, history-geo, visit-modal-errors, visit-manager-employees) — по 2 тега и выполняются дважды (двойные обработчики → возможны двойные сабмиты). Яндекс.Метрика подключена дважды (визиты считаются вдвое).

  • Убрать повторный вывод шапки и повторное подключение скриптов. Проверить, что счётчик Метрики остался один.

7. AG-8 · Битриксовые стили перекрывают вёрстку — Low

pubstyles.css, admin-public.css, hot_keys.css, popup.css подключены после app.css и без CSS-слоёв → перебивают вёрстку. Видно ТОЛЬКО пользователям с админ-панелью (тестировщикам).

  • Подключать админ-стили только в режиме правки. Ценность — убрать фантомные баги в QA.

8. AG-12 · Ревью на SQL-инъекции — Low

Активной проверкой SQLi не найдено (id→int, даты валидируются, filter_* до SQL не доходят). Для полноты — код-ревью, что все параметры уходят в БД параметризованно / через ORM; при желании sqlmap на стенде.

Не бэку (справочно): AG-6 (выкат свежего dist), AG-9 (синяя иконка сайдбара), AG-11 (XSS), лоадер задач, AG-1 фронт-часть — всё сделано на фронте и в сборке.
