Контракт API для бэкенда

Фронт не завязан на внутренности Битрикса — только на этот JSON-контракт. Хранение можно оставить на форумном модуле (b_forum_message уже держит текст, автора, родителя, модерацию), сверху добавить две таблицы под реакции и голоса. Мок в этом прототипе отдаёт ровно эти же ответы.

База и авторизация

  • База: /ajax/comments.php (или контроллер \Bitrix\Main\Engine\Controller).
  • Запись (create/react/vote) — обязательно с bitrix_sessid (CSRF). Контроллер Битрикса навяжет сам через configureActions.
  • Пагинация — курсорная, страницами. Дерево целиком не отдаём никогда.

3. Реакция (тоггл) — она же голос

Отдельного «голосования» нет: 👍 и 👎 — это обычные реакции, из них считается score. Один эндпоинт на всё.

POST /ajax/comments.php?action=react
{ "commentId":4841, "type":"like", "sessid":"…" }
// type: like|dislike|smile|clap|heart|party|hmm
// → { "ok": true, "reactions": {"like":10,"clap":2,"dislike":2},
//     "myReactions": ["like"], "score": 8 }   // score пересчитан бэком

Голоса и реакции — одна сущность, поэтому таблица одна, а не две. Меньше кода и рассинхрона.

Сортировка «Популярные» (hot)

Ранжирование в стиле Reddit — score (👍 − 👎) с затуханием по времени, считается на бэке в запросе:

hot = log10(max(|score|, 1)) + sign(score) * (unixCreated - 1700000000) / 45000

Модерация, права, авторизация — на стороне Битрикса

Фронт эти правила не реализует, а только отражает флаги из ответа. Логика прав и модерации остаётся в Битриксе, где уже есть сессия и роли.

  • Пишут только авторизованные. Проверяет сессия Битрикса; неавторизованный запрос на запись отклоняется. Фронт по currentUser прячет форму для гостя.
  • Правка и удаление для админов. Права считает бэк и кладёт canEdit / canDelete в каждый комментарий — фронт по ним показывает кнопки. Экшены: action=edit / delete.
  • Предмодерация. Настройка форумного модуля. Новый комментарий приходит со status: "pending" — фронт помечает «на модерации».
  • Отключить комментарии у новости. Флаг commentsEnabled: false — фронт прячет форму и показывает «комментарии отключены».
  • Минимум 10 символов. Фронт проверяет перед отправкой (UX), бэк — авторитетно (значение в minLength).
  • Запись идемпотентна и возвращает актуальные счётчики — фронт применяет оптимистично и откатывает при ошибке.
Миграция старых комментариев — почти ноль. Текущие комментарии в новостях уже хранятся форумным модулем (FORUM_POST). Раз мы оставляем это хранение, переносить нечего — сверху добавляется одна таблица реакций. В своей БД с нуля пришлось бы мигрировать.
Почему это не повторит лаг таблиц. Тот лаг был от выдачи ~1 МБ одним куском (TTFB 6–14 с). Здесь каждый запрос — одна лёгкая страница (≤ limit записей) с уже вложенными реакциями. Маленькое отдаётся быстро само по себе. Требование в ТЗ: страница ≤ 20–30, индексы по (entity, parent, score), реакции агрегированы в ответе — никаких N+1.

Как делаем

Сейчас в новостях стоят штатные комментарии Битрикса: умеют ветки и одну «лайк», но выглядят по-битриксовому и не дают реакций с сортировкой. Решение ниже — не список опций, а то, как делаем.

Решение

Хранение оставляем на форумном модуле Битрикса, весь интерфейс делаем свой. Данные, ветки, модерация, права и старые комментарии уже там — не трогаем. Бэк добавляет тонкий JSON-API и одну таблицу реакций. Фронт рисует всё в дизайне ЛК. Так получаем полный набор фич при низком риске, без «битриксового» вида и без миграции.

Не берём ни «оставить штатное» (нет реакций и вид не наш), ни «писать с нуля своей БД» (лишняя миграция и риск на ровном месте).

Голоса и реакции — одно и то же

Одна панель реакций, без отдельных стрелок. 👍 и 👎 в панели и есть голосование: рейтинг = 👍 минус 👎, по нему же сортировка. На Reddit это стрелки, у нас — те же 👍/👎 в общей панели эмодзи (ровно как ты нарисовал). Отдельные стрелки не делаем — иначе «нравится» дублировалось бы дважды.

Кто что делает

Фронт (мы)

  • Весь UI: ветки, реакции, рейтинг, сортировка
  • Оптимистичный отклик (мгновенно, как в демо)
  • Ленивая подгрузка (переиспользуем пейджер AG-1)
  • Сворачивание веток, компоновка, дизайн

Бэк (Александр)

  • Флаги прав/модерации + CSRF (штатно в Битриксе)

Про готовые модули (sadieff / scoder)

Смотрел. Реакции и голоса в них всё равно надо допиливать (из коробки максимум «лайк»), фронт у них свой — тот самый битриксовый вид, от которого уходим, плюс платная зависимость. Модерацию, ради которой их берут, форумный модуль даёт бесплатно. Поэтому пользы недостаточно, чтобы тянуть зависимость — гибрид выгоднее.

План

  • Реакции: твои 7 — 👍 😀 👏 ❤️ 🎉 🫤 👎. 👍/👎 = голос, рейтинг = их разница.
  • Старт: включаем в новостях. Позже теми же компонентами — где скажешь (визиты, задачи).
  • Реалтайм (новые комментарии живьём) — вторая фаза, через модуль Push&Pull. Для старта не нужен.

Дальше портируем этот прототип в проект (мок в vite.config + модуль data-module="Comments"), а контракт из вкладки «Для бэкенда» уходит Александру как ТЗ. Если по набору реакций или старту есть правки — скажи, подгоню.
