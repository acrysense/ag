## B. Для бэка — важное

### AG-1 · ERP-страницы генерируются 6–14 c на сервере
**Приоритет:** Critical

Время до первого байта на ERP-страницах — 6–14 c (чистая работа PHP до того, как запустится наш JS).
`/lk/` для сравнения — 0.12 c. Наш рендер таблиц быстрый (строки тянутся отдельным ajax ~1 КБ);
тормозит серверная сборка страницы, потому что бэк вшивает в HTML ~2280 опций сотрудников +
~1161 опцию фильтров из БД на каждый заход, без кеша.

| Страница | Сервер | HTML |
|---|---|---|
| /erp/visits/ | 8–14 c | 1.1 МБ |
| /erp/tasks/ | 6.3 c | 1.0 МБ |
| /erp/managers/ | 6.6 c | 108 КБ |
| /erp/pharmacies/ | 5.8 c | 145 КБ |
| /erp/employee/ | 5.7 c | 357 КБ |

**Совместная задача.** Фронт-часть (ведём мы): переделать фильтр-селекты и селект сотрудника в модалке
на ленивую загрузку опций по AJAX при открытии поля + виртуализация длинных списков. Бэк-часть: отдать
эндпоинт со списком (сотрудники/аптеки/менеджеры) и перестать вшивать опции в HTML; закешировать
справочники. Цель: время сервера < 1 c, вес визитов < 200 КБ.

### AG-2 · Нет HTTP-заголовков безопасности
**Приоритет:** High

Нет `Content-Security-Policy`, `X-Frame-Options`, `Strict-Transport-Security`, `X-Content-Type-Options`,
`Referrer-Policy`. `X-Powered-By: PHP/8.3.32` и `Server: nginx/1.26.3` раскрывают версии.
Риски: кликджекинг, downgrade на http, помощь в подборе эксплойтов.

**Сделать.** `X-Frame-Options: SAMEORIGIN` (или CSP `frame-ancestors 'self'`), HSTS,
`X-Content-Type-Options: nosniff`, `Referrer-Policy`; `server_tokens off`, скрыть `X-Powered-By`.
Хорошее (не трогать): сессионная кука `HttpOnly`.

### AG-3 · Перепроверить разграничение доступа + ПДн в HTML
**Приоритет:** High

На руководительской учётке скоуп корректный (ajax-таблица 8 строк, экспорт 3.5 КБ). Но в HTML вшиты все
15 менеджеров, 980 сотрудников, карта «менеджер→сотрудники» на 542 человека, и **реальные телефоны
сотрудников** (`375…`) в данных визитов. Нужно убедиться, что рядовому менеджеру сервер режет выборку,
а не только UI.

**Проверить (учётка обычного менеджера, read-only):** `/ajax/visits.php` с чужим `filter_manager`,
большим `limit`, `showAll`; `/ajax/export-excel.php` с подменёнными фильтрами; `detail.php?id=…` чужого
визита/сотрудника по прямой ссылке (IDOR). Критерий — сервер режет по роли независимо от параметров.
Не отдавать в HTML ПДн (телефоны), не нужные для отрисовки.

### AG-4 · Дублируется `<head>` и скрипты визитов (+ двойная Метрика)
**Приоритет:** Medium

`ShowHead()` выводится дважды: битриксовые `<link>`, `bx-core`, meta — по 2 раза; скрипты визитов
(`calendar-cta`, `history-geo`, `visit-modal-errors`, `visit-manager-employees`) — по 2 тега и
**выполняются дважды** (подтверждено: в модалке 4 тега вместо 2 → двойной биндинг обработчиков,
возможны двойные сабмиты). Яндекс.Метрика тоже подключена дважды → визиты считаются вдвое.

**Сделать.** Убрать повторный вывод шапки и повторное подключение скриптов. Двойная Метрика уйдёт вместе
с этим — проверить, что счётчик остался один.

### AG-7 · Нет поля «Период» в фильтре визитов

В фильтре визитов поля: Категория / Сотрудник / Аптека / Розница / Менеджер. Поля «Период» нет →

у пользователя нет). Подключать админ-стили только в режиме правки.
